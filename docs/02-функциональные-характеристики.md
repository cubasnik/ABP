# Документация по функциональным характеристикам

## Введение
Документ описывает функции программного обеспечения «Обозреватель технической документации» и соответствует реализованной функциональности версии 1.0.

## 1. Назначение
ПО предназначено для хранения, поиска, чтения и анализа технической документации телекоммуникационного оборудования (RAN, Core, транспорт) с помощью полнотекстового поиска, фасетной фильтрации, древовидной навигации и ассистента на основе искусственного интеллекта.

## 2. Общая функциональность
2.1. Запуск и останов программы: сервер запускается командой `python -m app` или `uvicorn`, останавливается сигналами SIGTERM/SIGINT (Ctrl+C) либо командой администратора `POST /api/admin/shutdown`; при останове закрываются соединения с базой и поисковым слоем.
2.2. Конфигурация загружается из файла `.env` и переменных окружения.
2.3. Журнал событий ведётся в консоль и файл `logs/app.log` с ротацией (5 файлов по 5 МБ).
2.4. Встроенный REST API сервер с командами мониторинга и управления; описание OpenAPI доступно по адресу `/api/docs-ui`.

## 3. Работа с документацией
3.1. Левая панель — дерево документации: продукт → версия → домен → тема → документы.
3.2. Верхняя панель — глобальный поиск и переключатель версии релиза; выбранная версия ограничивает дерево, поиск и ассистента.
3.3. Центральная область — режим чтения статьи: заголовок, метаданные, список разделов-якорей, текст по разделам.
3.4. Полнотекстовый поиск с фасетной фильтрацией по полям product, vendor, domain, release, node_type, interface, protocol, topic; в результатах — подсветка фрагмента и ссылка на раздел.
3.5. Метаданные задаются в заголовке документа (front-matter) или при загрузке.
3.6. Поддерживаемые форматы документов: Markdown, HTML, текст.

## 4. Управление пользователями
4.1. Регистрация пользователей (первый пользователь — администратор; регистрацию можно отключить).
4.2. Аутентификация по логину и паролю; пароли хранятся в виде хэша PBKDF2-SHA256.
4.3. Подтверждение входа по СМС-коду для учётных записей с признаком «СМС-код при входе»; код действует 5 минут, не более 5 попыток ввода.
4.4. Вход по QR-коду: новое устройство показывает код, устройство с выполненным входом подтверждает.
4.5. Ролевая модель: «пользователь» (чтение, поиск, ассистент) и «администратор» (дополнительно пользователи, загрузка документов, мониторинг, управление).
4.6. Управление пользователями администратором: создание, изменение, отключение, смена пароля, разблокировка, удаление.
4.7. Блокировка учётной записи на 15 минут после 5 неудачных попыток входа (параметры настраиваются).
4.8. Автоматическое завершение сеанса при отсутствии активности 30 минут; выход через кнопку с именем пользователя.

## 5. Искусственный интеллект
5.1. Правая панель — ассистент.
5.2. Ответы с привязкой к источникам: для каждого ответа возвращаются фрагменты документов и ссылки на разделы; номера источников в ответе открывают нужный раздел.
5.3. Режимы: explain (объяснение), compare (сравнение), diagnose (диагностика).
5.4. Уровень уверенности ответа (0–100) по силе совпадения источников и доле процитированных.
5.5. Обратная связь like/dislike по каждому ответу.
5.6. Строгая политика источников strict-required-citations: ответ без ссылок вида [n] или с пометкой об отсутствии данных блокируется и пользователю не выдаётся.
5.7. Провайдеры модели: mock (без сети, извлечение из найденных фрагментов), OpenAI-совместимый API, Anthropic.

## 6. Мониторинг и управление
6.1. Метрики: количество документов и фрагментов, задержка поиска (среднее, p50, p95, максимум), число ответов ИИ и блокировок.
6.2. Панели: ошибки, задержки и пропускная способность по маршрутам.
6.3. Список узких мест по стадиям обработки (поиск, повторное ранжирование, retrieval, генерация, проверка, индексация).
6.4. Журнал административных действий (кто, что, когда, с какого адреса).
6.5. Журнал ответов искусственного интеллекта с оценками.
6.6. Идемпотентность загрузки документов: повторная загрузка неизменённого файла не создаёт дубликатов.
6.7. Повторные попытки при временных сбоях OpenSearch (по умолчанию 3) и автоматический запасной индекс в памяти.
6.8. Режим обслуживания и корректный останов сервера из интерфейса администратора.

## 7. Интерфейс
7.1. Навигация по дереву, переключение версии, чтение с якорями, сохранение поисков и закреплённых разделов в localStorage браузера.
7.2. Адаптивный макет: на экранах уже 900 px три панели переключаются вкладками.

## Приложение А. Перечень маршрутов REST API
| Маршрут | Назначение |
|---|---|
| `GET /api/health` | состояние службы |
| `POST /api/auth/register`, `/login`, `/sms/confirm`, `/qr/new`, `GET /qr/poll/{token}`, `POST /qr/confirm`, `/refresh`, `/logout`, `GET /me` | вход и сеансы |
| `GET/POST /api/users`, `PUT/DELETE /api/users/{id}` | пользователи (администратор) |
| `GET /api/docs/tree`, `/search`, `/facets`, `/{id}`, `POST /upload`, `/ingest-dir`, `DELETE /{id}` | документация |
| `POST /api/ai/ask`, `/feedback`, `GET /history`, `/log` | ассистент |
| `GET /api/admin/status`, `/metrics`, `/monitoring`, `/bottlenecks`, `/audit`, `POST /reindex`, `/maintenance`, `/shutdown` | мониторинг и управление |
