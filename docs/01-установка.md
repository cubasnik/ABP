# Документация по установке экземпляра программного обеспечения

## Введение
Документ описывает установку программного обеспечения «Обозреватель технической документации» (далее — ПО) на целевых платформах Linux и Windows: развёртывание в Docker и установку из исходного кода.

## 1. Требования к окружению
1.1. Сервер: Linux (Ubuntu 22.04 и новее, Debian 12) или Windows 10/11, Windows Server 2019 и новее.
1.2. Для развёртывания в Docker: Docker Engine 24+ и Docker Compose v2, не менее 4 ГБ оперативной памяти (OpenSearch занимает около 1 ГБ).
1.3. Для установки из исходного кода: Python 3.11 или 3.12, Node.js 20, доступ к OpenSearch 2.x (необязательно: без него поиск работает в памяти процесса).
1.4. Сетевые порты: 3000 (клиент), 8000 (API), 9200 (OpenSearch, только внутри контура).

## 2. Установка в Docker
2.1. Получить исходный код: `git clone https://github.com/cubasnik/ABP.git && cd ABP`.
2.2. Создать файл настроек: `cp .env.example .env`, задать `SECRET_KEY` (длинная случайная строка), при необходимости параметры ИИ и СМС.
2.3. Запустить: `docker compose up -d --build`. Запускаются три контейнера: `opensearch`, `backend`, `frontend`.
2.4. Проверить: `curl http://localhost:8000/api/health` должен вернуть `{"status":"ok", ...}`; клиент открывается по адресу http://localhost:3000.
2.5. Зарегистрировать первого пользователя через клиент — он получает роль администратора. Дальнейшую регистрацию можно запретить параметром `ALLOW_REGISTRATION=false`.

## 3. Установка из исходного кода
3.1. Сервер API:
```
cd backend
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp ../.env.example ../.env       # и отредактировать
python -m app                    # или: uvicorn app.main:app --host 0.0.0.0 --port 8000
```
3.2. Клиент:
```
cd frontend
npm ci
NEXT_PUBLIC_API_URL=http://localhost:8000 npm run build
npm run start
```
3.3. Для постоянной работы на Linux оформить сервисы systemd (пример в разделе 4), на Windows — службу через NSSM или задачу планировщика.

## 4. Пример службы systemd для сервера
```
[Unit]
Description=ABP backend
After=network.target

[Service]
WorkingDirectory=/opt/ABP/backend
EnvironmentFile=/opt/ABP/.env
ExecStart=/opt/ABP/backend/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=on-failure
KillSignal=SIGTERM
TimeoutStopSec=20

[Install]
WantedBy=multi-user.target
```

## 5. Параметры конфигурации (.env)
| Параметр | Назначение | По умолчанию |
|---|---|---|
| `SECRET_KEY` | ключ подписи сеансов | обязательно сменить |
| `DATABASE_URL` | база данных | `sqlite:///./data/abp.db` |
| `SEARCH_BACKEND` | `auto` / `opensearch` / `memory` | `auto` |
| `OPENSEARCH_URL` | адрес OpenSearch | `http://localhost:9200` |
| `DOCS_DIR` | папка документов, загружаемая при старте | `../sample-docs` |
| `SMS_PROVIDER` | `console` (код в журнал) / `http` (шлюз) | `console` |
| `AI_PROVIDER` | `mock` / `openai` / `anthropic` | `mock` |
| `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL` | подключение модели | пусто |
| `ACCESS_TOKEN_MINUTES` | время бездействия до завершения сеанса | 30 |
| `CORS_ORIGINS`, `FRONTEND_URL` | адрес клиента | `http://localhost:3000` |

Полный перечень — в файле `.env.example`.

## 6. Проверка установки
6.1. `GET /api/health` возвращает `status: ok` и имя поискового слоя.
6.2. В разделе «Администрирование → Состояние» видны версия, число документов и состояние поиска.
6.3. Поиск по слову «SCTP» в образцах документации возвращает результаты с фасетами.

## Приложение А. Обновление
Остановить службы, обновить код (`git pull`), повторить шаги установки зависимостей и сборки, запустить службы. Схема базы данных создаётся и дополняется автоматически при старте.
