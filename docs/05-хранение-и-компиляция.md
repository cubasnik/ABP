# Документация по средствам хранения и компиляции исходного кода

## Введение
Документ описывает, где хранится исходный код программного обеспечения «Обозреватель технической документации», как он собирается в исполняемые файлы и образы и как воспроизвести сборку.

## 1. Хранение исходного кода
1.1. Система контроля версий — Git; репозиторий: https://github.com/cubasnik/ABP.
1.2. Структура репозитория:
```
ABP/
  backend/            сервер API (Python, FastAPI)
    app/              исходный код: config, db, models, security, routers/, search/, ingest/, ai/
    tests/            автотесты (pytest)
    requirements*.txt зависимости
    Dockerfile
  frontend/           клиент (TypeScript, Next.js)
    app/              страницы: /, /login, /qr, /admin
    components/       Tree, Facets, Reader, AiPanel
    lib/              api.ts (сеанс, API), storage.ts (localStorage)
    Dockerfile
  sample-docs/        образцы документации
  docs/               эксплуатационная документация
  .github/workflows/  CI
  docker-compose.yml, .env.example, README.md
```
1.3. Ветки и правила описаны в документе о жизненном цикле. История коммитов осмысленная: одна задача — один коммит.
1.4. Резервное копирование репозитория: зеркало `git clone --mirror` на отдельный сервер еженедельно; артефакты сборки хранятся в GitHub Actions.

## 2. Языки и инструменты
| Часть | Язык | Версии | Инструменты |
|---|---|---|---|
| Сервер | Python | 3.11, 3.12 | pip, ruff, pytest, uvicorn |
| Клиент | TypeScript | 5.6 | Node.js 20, npm, Next.js 14 |
| Контейнеры | Dockerfile | Docker 24+ | docker, docker compose |

## 3. Сборка сервера
3.1. Сервер — интерпретируемый код; «сборка» заключается в установке зависимостей и проверке:
```
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
ruff check app tests
pytest -q
```
3.2. Исполняемый файл для целевой платформы собирается PyInstaller (по желанию):
```
pip install pyinstaller
pyinstaller --onefile --name abp-server --collect-all app -m app
```
Результат — `dist/abp-server` (Linux) или `dist/abp-server.exe` (Windows). Для регистрации РИД исполняемый код также представлен Docker-образом.
3.3. Docker-образ: `docker build -f backend/Dockerfile -t abp-backend .` (контекст — корень репозитория).

## 4. Сборка клиента
```
cd frontend
npm ci
npx tsc --noEmit
NEXT_PUBLIC_API_URL=https://адрес-api npm run build
```
Результат — папка `.next/` (режим standalone: `.next/standalone/server.js` + `.next/static`). Docker-образ: `docker build -t abp-frontend ./frontend`.

## 5. Воспроизводимость
5.1. Зависимости закреплены точными версиями: `requirements.txt`, `package-lock.json`.
5.2. CI собирает всё на чистых машинах Linux и Windows при каждом изменении — это эталон воспроизводимости.
5.3. Образы собираются из конкретного коммита; тег образа совпадает с тегом версии.

## 6. Требования к коду
6.1. Единый стиль: ruff для Python (длина строки 140, правила E, F, W, I, B, UP), строгий TypeScript (`strict: true`).
6.2. Функции и сложные участки снабжены комментариями на русском языке; закомментированного кода нет.
6.3. Ошибки обрабатываются явно: исключения приводятся к понятным ответам API, аудит и журнал не прерывают основное действие.

## Приложение А. Команды одной строкой
- Полная проверка сервера: `cd backend && ruff check app tests && pytest -q`
- Полная проверка клиента: `cd frontend && npm ci && npx tsc --noEmit && npm run build`
- Всё в Docker: `docker compose up -d --build`
