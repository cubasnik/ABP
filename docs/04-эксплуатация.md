# Документация по эксплуатации экземпляра программного обеспечения

## Введение
Руководство для пользователей и администраторов программного обеспечения «Обозреватель технической документации».

## 1. Вход в программу
1.1. Откройте адрес клиента (по умолчанию http://localhost:3000). Выберите способ входа: «Пароль», «QR-код» или «Регистрация».
1.2. Вход по паролю: введите логин и пароль. Если для учётной записи включён СМС-код, появится поле для кода, отправленного на телефон (в режиме `SMS_PROVIDER=console` код печатается в журнал сервера).
1.3. Вход по QR-коду: на новом устройстве откройте вкладку «QR-код», отсканируйте его устройством, где вход уже выполнен, и нажмите «Да, это я». Новое устройство войдёт автоматически.
1.4. После 5 неудачных попыток учётная запись блокируется на 15 минут; разблокировать раньше может администратор.
1.5. Без активности 30 минут сеанс завершается, потребуется войти снова. Выход — кнопка с именем пользователя в верхней панели.

## 2. Работа с документацией
2.1. Дерево слева: продукт → версия → домен → тема → документы. Щелчок по документу открывает его в центральной области.
2.2. Переключатель версии в верхней панели ограничивает дерево, поиск и ассистента выбранным релизом; выбор запоминается в браузере.
2.3. Поиск: введите запрос и нажмите «Найти». В результатах — подсветка найденных слов, раздел документа, метаданные. Фасеты над результатами сужают выборку по продукту, домену, версии, типу узла, интерфейсу, протоколу и теме; повторный щелчок снимает фильтр.
2.4. Последние 20 поисков сохраняются в браузере и доступны под деревом.
2.5. Чтение: список разделов-якорей под заголовком, кнопка 📍 закрепляет раздел — закреплённые разделы показываются первыми и помечаются 📌 (хранится в браузере).

## 3. Ассистент
3.1. Выберите режим: «Объяснить», «Сравнить» или «Диагностика», введите вопрос, нажмите «Спросить» (или Ctrl+Enter).
3.2. Ответ содержит ссылки [n] на источники; щелчок по номеру или по карточке источника открывает нужный раздел документа.
3.3. Полоса «Уверенность» показывает, насколько ответ подкреплён источниками.
3.4. Если в документации нет подходящих фрагментов, ответ блокируется с пояснением — это политика strict-required-citations. Уточните вопрос или смените версию.
3.5. Оцените ответ кнопками «Полезно» / «Нет» — оценки видны администратору в журнале ИИ.

## 4. Администрирование
Раздел «⚙ Администрирование» доступен роли «администратор».
4.1. Состояние: версия, поисковый слой и его доступность, число документов и фрагментов, пользователей, провайдер ИИ; кнопки «Переиндексировать», «Обслуживание», «Остановить сервер».
4.2. Пользователи: создание, смена роли, отключение/включение, смена пароля, разблокировка, удаление, признак «СМС-код при входе».
4.3. Документы: загрузка файла .md/.html/.txt с метаданными (из заголовка файла или полей формы); загрузка папки `DOCS_DIR` с сервера. Повторная загрузка неизменённого файла ничего не дублирует.
4.4. Мониторинг: запросы и ошибки, время работы, узкие места по стадиям, таблица маршрутов (ошибки, p95, запросов в минуту).
4.5. Журнал действий: кто, когда, что сделал, с какого адреса.
4.6. Журнал ИИ: вопросы, итог (ответ или блокировка), уверенность, задержка, оценка.

## 5. Формат документа
```
---
title: Название
product: Baseband Radio Node
vendor: Ericsson
domain: RAN
release: 24.Q3
node_type: eNodeB
interface: S1
protocol: SCTP
topic: Интеграция
---
# Название
## Раздел 1
Текст…
```
Заголовки `#`…`####` образуют разделы и якоря.

## 6. Типовые неполадки
| Признак | Причина | Действие |
|---|---|---|
| В состоянии поиск = memory, хотя ожидался OpenSearch | OpenSearch недоступен при старте | проверить `OPENSEARCH_URL`, перезапустить сервер, нажать «Переиндексировать» |
| Ассистент всегда блокирует ответы | нет подходящих документов или модель недоступна | загрузить документацию; проверить `AI_*` в `.env` и журнал |
| Не приходит СМС | `SMS_PROVIDER=console` | в журнале сервера строка «СМС (console) …: код …»; для реальной отправки задать `http` и адрес шлюза |
| 503 «регламентные работы» | включён режим обслуживания | выключить в «Состояние» |
| Сеанс завершён | 30 минут без активности | войти снова |

## Приложение А. Журналы
Журнал сервера: `backend/logs/app.log` (в Docker — том `backend-logs`). Уровень задаётся `LOG_LEVEL`.
