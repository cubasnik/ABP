# Операционная инструкция: резервное копирование и восстановление

## Введение
Инструкция описывает, какие данные программного обеспечения «Обозреватель технической документации» подлежат резервному копированию, как делать копии и как восстанавливаться.

## 1. Что хранится и где
| Данные | Docker | Установка из кода | Обязательность копии |
|---|---|---|---|
| База данных (пользователи, документы, аудит, журнал ИИ) | том `backend-data` → `/app/data/abp.db` | `backend/data/abp.db` | обязательно |
| Журналы сервера | том `backend-logs` | `backend/logs/` | желательно |
| Индекс OpenSearch | том `opensearch-data` | каталог OpenSearch | необязательно: пересобирается из базы |
| Настройки | `.env` | `.env` | обязательно (хранить отдельно, содержит секреты) |
| Исходные документы | `sample-docs/` или `DOCS_DIR` | то же | желательно |

## 2. Резервное копирование
2.1. База SQLite копируется в согласованном состоянии командой SQLite, а не копированием файла во время работы:
```
# Docker
docker compose exec backend python -c "import sqlite3;s=sqlite3.connect('/app/data/abp.db');d=sqlite3.connect('/app/data/backup.db');s.backup(d);d.close()"
docker compose cp backend:/app/data/backup.db ./backups/abp-$(date +%F).db
# Установка из кода
python -c "import sqlite3;s=sqlite3.connect('backend/data/abp.db');d=sqlite3.connect('backups/abp-$(date +%F).db');s.backup(d);d.close()"
```
2.2. Файл `.env` и папка документов копируются обычным способом в то же место с датой.
2.3. Рекомендуемый график: база — ежедневно, перед каждым обновлением — обязательно; хранить не менее 30 копий; одну копию в неделю переносить на другой сервер.
2.4. Проверка копии: открыть её командой `sqlite3 backups/abp-<дата>.db "PRAGMA integrity_check; SELECT COUNT(*) FROM documents;"` — ответ `ok` и число документов.

## 3. Восстановление
3.1. Остановить сервер: `docker compose stop backend` или остановить службу.
3.2. Положить копию на место базы: `/app/data/abp.db` (через `docker compose cp ./backups/abp-<дата>.db backend:/app/data/abp.db`) или `backend/data/abp.db`. Удалить файлы `abp.db-wal` и `abp.db-shm`, если они есть.
3.3. Восстановить `.env`.
3.4. Запустить сервер. Индекс поиска: в режиме памяти поднимается автоматически; для OpenSearch нажать «Администрирование → Переиндексировать» (или `POST /api/admin/reindex`).
3.5. Проверить: `GET /api/health`, вход администратора, число документов в «Состояние», поиск.

## 4. Полная переустановка
При потере сервера: установить ПО по документации по установке, восстановить `.env` и базу по разделу 3, загрузить документы (если индекс OpenSearch утерян — переиндексировать). Исходный код всегда доступен в репозитории.

## 5. Восстановление доступа администратора
Если пароль администратора утерян, на сервере выполнить:
```
cd backend && . .venv/bin/activate
python -c "from app.db import SessionLocal;from app.models import User;from app.security import hash_password;db=SessionLocal();u=db.query(User).filter_by(username='admin').one();u.password_hash=hash_password('НовыйПароль123');u.locked_until=None;u.failed_logins=0;db.commit()"
```
(в Docker — через `docker compose exec backend python -c "..."`).
